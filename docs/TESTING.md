# 测试与验收

当前阶段不编译。静态检查只能检查文件、XML、事件名称、路径与忽略配置；不能证明 C# 或 WinUI 编译成功，也不能代替人工验收。

## 本机入口

`Test-ToDoList.ps1` 按要求加入 `.gitignore`，仅存在于当前工作区，不会随克隆仓库获得；核心检查源码和本说明正常纳入 Git。

在项目根目录执行：

```powershell
# 默认：不还原、不编译、不启动程序。
powershell -ExecutionPolicy Bypass -File .\Test-ToDoList.ps1

# 仅在明确批准编译后使用：编译并运行核心检查。
powershell -ExecutionPolicy Bypass -File .\Test-ToDoList.ps1 -Mode Core -AllowBuild

# 已有编译产物时：从临时工作目录启动，验证内部相对路径。
powershell -ExecutionPolicy Bypass -File .\Test-ToDoList.ps1 -Mode UI -AppPath .\artifacts\portable\ToDoList\ToDoList.exe
```

核心检查在独立的 `artifacts/checks-时间戳` 中创建测试数据库、备份和文档，不接触真实计划。使用无测试框架依赖的 console runner，失败退出码为 1，保留产物用于检查。

## 自动核心检查范围（等待编译批准）

- SQLite 关闭重开、整个数据目录移动后，内容、换行、用时与排序不变。
- 独立日期互不覆盖；事务失败恢复旧数据；自动备份可独立打开。
- 不连续日期去重、排序；默认空白过滤、包含空白日期；只填用时的校验。
- 文件名保留字符和设备名校验；单日、连续、不连续标题。
- DOCX Open XML schema 校验，顺序、日期、方框、字号与字体嵌入。
- PDF 文件可读取，A4 大小；长中文计划跨页。
- 未授权覆盖保留原文件；第二个输出文件锁定时撤销第一个输出的替换。

## 人工 UI 验收（等待编译批准）

1. 打开应用：右侧编辑区默认比月历宽，浅色和深色均清晰；在 100% / 150% 缩放下布局完整。
2. 拖动分隔线改变宽度，关闭重开后宽度恢复，输入区仍可使用。
3. 点击日期、前后一天、前后月份和“今天”，检查日期、星期和计划对应。
4. 新建三行，分别输入多行中文、自由文本预计用时和空用时；按 Tab 和中文输入法正常编辑。
5. 只拖动序号，将第三行移到第一行，检查序号重排和输入框内容对应。
6. 删除有内容行时取消一次、确认一次；删除最后一行后仍有空白输入行。
7. 输入后等待自动保存，切换日期并返回；再次输入后立即正常关闭，重开检查保存。
8. 同一目录再次启动应提示数据目录正在使用；将程序放在不可写目录应给出提示。
9. 点击完成后返回编辑，再次进入导出页，计划不丢失。
10. 默认周一至周日；跨月和跨年选择；点选不连续日期；应用连续范围会替换勾选。
11. 改名后继续勾日期，自定义文件名不被自动覆盖；检查非法文件名、未选日期、未选格式的提示。
12. 只填预计用时的行阻止该日期导出；纯空白行忽略；空日期选项关闭时跳过，开启时保留日期及手写空间。
13. 分别导出 Word、PDF、同时导出；默认 Exports；选择另一个盘符目录；取消文件夹选择。
14. 已有同名文件时先取消再确认，确认取消不修改旧文件。将目标文件用独占方式锁定，检查失败提示和恢复。
15. 导出过程中界面仍可响应，确认导出按钮不能重复触发，窗口不能提前关闭；完成后打开文件与目录入口有效。

## 打印与便携验收（等待编译批准）

- 用 Word 与 PDF 阅读器打开核心测试生成的样例；核对中文、26 磅居中标题、日期冒号和星期、方框、计划顺序、预计用时右对齐。
- 观察长内容的首尾与跨页位置，确保无缺字、裁切、重复方框或日期标题孤悬。
- 导出空白日期，检查三行手写空间；跨多月不连续标题能换行。
- 打印预览应为 A4 纵向，方框可用笔勾选；PDF 为最终打印参考。
- 关闭程序，将完整便携发布文件夹复制到另一个可写路径，从完全不同的工作目录运行，数据仍在 Data 中。
- 在没有开发 SDK、.NET 和 Office 的另一台兼容 x64 Windows 电脑测试启动、编辑和两种导出；确认所有运行依赖及 Assets/Fonts 随发布文件夹存在。
- 移动前先正常关闭程序，不在程序运行中复制 SQLite 数据文件。
